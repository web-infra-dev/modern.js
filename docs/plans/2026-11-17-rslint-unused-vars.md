# 修复 Rslint 未使用变量漏检

## Decision Brief

**Intent**：让仓库的代码检查能够发现未使用的变量、导入和参数，避免检查通过却遗漏死代码。

**Outcome**：现有代码通过检查，新增未使用变量时检查失败。

**Scope**：修复仓库的 lint 项目发现配置，处理由此暴露的历史诊断，加入回归检查。清理代码时保留调用副作用和对象属性剔除行为。

## 执行计划

这是中等规模的配置缺陷修复。根因已通过当前 Rslint 版本的对照实验确认：根目录缺少 tsconfig，且 lint 没有开启项目发现，未使用变量规则因此未执行。各包已有 tsconfig，可以复用。

涉及范围：`rstack.config.mts`、`package.json`、`.github/workflows/lint-Linux.yml`、`tests/lint/`，以及启用项目发现后产生诊断的源码、脚本和测试。

1. 开启项目发现并收集全仓诊断，确认未被项目覆盖的文件如何检查。
2. 清理存量诊断。删除无用导入和无副作用的变量，保留有意忽略的参数、捕获异常以及解构剔除属性的行为。不修改框架运行时语义。
3. 添加通过真实 CLI 运行的回归检查，在根目录没有 tsconfig 的场景中验证子包未使用变量会失败、有效代码会通过，并接入 lint CI。
4. 执行最终验证并检查改动范围。

风险与处理：未使用绑定可能承担属性剔除或调用副作用，逐处确认后再修改。测试夹具中可能有意保留未使用绑定，使用明确命名或局部规则配置表达意图。不要全局关闭未使用变量规则。

不修改依赖版本、锁文件、构建产物、发布历史，不进行无关重构。
