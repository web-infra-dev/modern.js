# Open Graph images with Modern.js

[中文说明](./README.zh-CN.md)

An article page with a 1200 × 630 PNG share image, generated on the server with [Satori](https://github.com/vercel/satori) and [Resvg](https://github.com/thx/resvg-js). The initial HTML contains its title, description, canonical URL and absolute `og:image` URL. Share crawlers do not need to execute JavaScript.

![Generated article share image](./preview.png)

[Long-title preview](./preview-long-title.png). These previews were generated by the BFF endpoint using the bundled fonts.

## Run

Use Node.js 22.18 or later in the 22.x line, or Node.js 24.3 or later, as declared in `package.json`. The Modern.js packages are pinned to 3.11.3 to keep the validated example reproducible when `latest` changes.

From the repository root:

```bash
pnpm install
cd examples/og-image
pnpm dev
```

If you copy this directory into a standalone project, run `pnpm install` there instead. The example does not need external APIs or credentials.

Open these pages:

- [Article](http://localhost:8080/posts/hello-modern)
- [Long title](http://localhost:8080/posts/long-title)
- [PNG endpoint](http://localhost:8080/api/og/hello-modern?v=1)

`SITE_URL` is the public HTTP(S) origin, with no path, query or credentials. It defaults to `http://localhost:8080`. Modern.js embeds it at development startup or build time so the server and browser use the same absolute metadata URLs. Set it to the externally reachable origin before building, including when a reverse proxy terminates HTTPS. Setting it only when starting an existing build does not change those URLs.

```bash
SITE_URL=https://journal.example.com pnpm build
pnpm serve
```

For local production checks, omit `SITE_URL` to use port 8080.

## Build and deploy

```bash
pnpm typecheck
pnpm build
pnpm serve
```

To create the self-contained Node.js deployment output:

```bash
SITE_URL=https://journal.example.com MODERNJS_DEPLOY=node pnpm run deploy
PORT=8080 node .output/index
```

`modern deploy` also runs the build. Copy the entire `.output` directory to the target machine. Build and install for the target operating system and architecture because `@resvg/resvg-js` uses a native binary. A successful local Node.js check does not verify Vercel, Netlify, other operating systems or edge runtimes.

The font files under `api/assets` are copied into `dist/api/assets` during the server build and into `.output/api/assets` during deployment. `api/og.tsx` resolves them relative to `__dirname`, so running the output from another working directory does not require source files or system fonts. Keep the accompanying font license with the deployment.

## Verify a running server

With the dev, production or deployment server running in another terminal:

```bash
node scripts/verify.mjs http://localhost:8080
node scripts/verify.mjs http://localhost:8080 /tmp/modern-og-preview
```

The verifier checks the raw HTML metadata, fetches the advertised image, checks PNG headers and dimensions, and exercises long titles and missing articles. The optional output directory saves previews for visual inspection. Use the same origin as the `SITE_URL` used to start development or build the app. To test deployment isolation, copy `.output` outside the repository, start its `index.js` there, and run this verifier against it.

## How it works

- `shared/posts.ts` contains local article data, image dimensions and image URL versioning.
- `src/routes/posts/[slug]/page.data.ts` supplies article data and absolute metadata URLs. An unknown slug throws a 404 response.
- `src/routes/posts/[slug]/page.tsx` uses `Helmet` with string SSR to place metadata in the initial HTML.
- `api/og.tsx` turns a JSX template into SVG with Satori, then rasterizes it with Resvg. It loads bundled fonts once per process and disables system font loading.
- `api/lambda/og/[slug].ts` serves the PNG at `/api/og/:slug`. It returns a standard `Response` containing a `Uint8Array` with `Content-Type: image/png`. Returning a bare `Buffer` would use BFF's ordinary JSON serialization instead of this binary response path. Unknown articles return 404 with `Cache-Control: no-store`.

Satori implements a [limited subset of HTML and CSS](https://github.com/vercel/satori#css). This template uses inline styles and flex layout. Longer titles use smaller type and a three-line clamp to protect the author row. The full title remains in the page and metadata. Arbitrary browser layouts or unbounded user input need additional layout checks.

The bundled Inter files contain Latin glyphs for this English example and use static WOFF fonts. For Chinese text, add an appropriately licensed static TTF, OTF or WOFF font containing the required glyphs, register its data and weights in `api/og.tsx`, and update `fontFamily`. Keep its license and inspect rendered output for missing glyphs and wrapping. See [font provenance](./api/assets/README.md).

## Caching and updates

Successful images use `Cache-Control: public, max-age=3600, s-maxage=86400`, allowing one hour in browsers and one day in shared caches that honor these directives. The example has no application image cache, so every uncached image request renders again. Only font data is reused in memory.

Image caching and SSR page caching are separate layers. These image headers do not enable or configure page rendering caches. Sharing services can also cache metadata and images independently of your CDN.

Increment `imageVersion` in `shared/posts.ts` when changing the template or fonts, and version article content when integrating a CMS. The `v` query parameter gives crawlers and caches a new image URL after the updated HTML is fetched. It does not keep historical image versions or forcibly purge existing caches. Configure a CDN to include `v` in its cache key, and refresh cached HTML and sharing-service previews as needed.
