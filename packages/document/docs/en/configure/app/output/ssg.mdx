# output.ssg

- **Type:** `boolean | object`
- **Default Value:** `undefined`

Configuration to enable the application’s SSG (Static Site Generation) feature.

:::tip Enabling SSG
This configuration takes effect only when SSG is enabled. Please read the [Static Site Generation](/guides/basic-features/render/ssg) documentation to understand how to enable SSG and its use cases.

:::

:::info Recommended Reading
The SSG feature is closely related to routing. It is recommended to understand the [routing solution](/guides/basic-features/routes/routes) before using SSG.

:::

:::info

- Use `output.ssg` for single-entry apps.
- For multi-entry apps, prefer `output.ssgByEntries`.
- If `output.ssg` is `true` and `output.ssgByEntries` is not set, SSG is enabled for all entries, using the route collection rules below.

:::

## Boolean Type

When this configuration is set to `true`, the SSG feature will be enabled for all entries by default. For **manual routing**, the root route of the entry will be rendered. For **conventional routing**, non-dynamic routes and paths returned by page-level `ssgParams` generators will be rendered. Dynamic routes without a generator are skipped.

```js
export default defineConfig({
  output: {
    ssg: true,
  },
});
```

## Object Type

When the value type is `Object`, the following attributes can be configured.

### Configuration Type

```ts
type SSGRouteOptions =
  | string
  | {
      url: string;
      headers?: Record<string, any>;
    };

type SSGOptions = {
  headers?: Record<string, any>;
  routes?: SSGRouteOptions[];
};
```

### Route Collection

- With `routes` omitted or set to `[]`, conventional routing automatically includes non-dynamic routes and paths generated by `ssgParams` in file-system `page.data.ts` or `$.data.ts` files. Generator discovery does not apply to config routes.
- A non-empty `routes` list replaces automatic collection for the entry. Only the listed paths are rendered, and `ssgParams` is not called.
- Setting the entry's SSG option to `false` also disables its parameter generators.

These rules also apply to each entry configured through `output.ssgByEntries`. See [generating parameters alongside a loader](/guides/basic-features/render/ssg#generating-parameters-alongside-a-loader) for parameter types, encoding, and examples.

### Example

In the example configuration below, SSG will render the pages corresponding to the `/`, `/about`, and `/user/:id` routes.

For the `/user/:id` route, `cookies` will be added to the request headers.

```ts title="modern.config.ts"
export default defineConfig({
  output: {
    ssg: {
      routes: [
        '/',
        '/about',
        {
          url: '/user/modernjs',
          headers: {
            cookies: 'name=modernjs',
          },
        },
      ],
    },
  },
});
```
