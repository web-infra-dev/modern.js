# server.ssr

- **Type:** `boolean`
- **Default:** `false`

Enalbe SSR configuration.

### Boolean Type

When the value type is `boolean`, it indicates whether to enable SSR deployment mode. The default is `false` to disable it.

```ts title="modern.config.ts"
export default defineConfig({
  server: {
    ssr: true,
  },
});
```

### Object Type

When the value type is `Object`, the following properties can be configured:

| Name                | Type                            | Default         | Description                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| ------------------- | ------------------------------- | --------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| mode                | `string`                        | `stream`        | which defaults to using streaming rendering. Configure `string` to use `renderToString` for rendering                                                                                                                                                                                                                                                                                                                                                                                          |
| forceCSR            | `boolean`                       | `false`         | which is off by default for forcing CSR rendering. Configure `true` to force CSR by adding `?csr=true` or adding `x-modern-ssr-fallback` header when accessing the page                                                                                                                                                                                                                                                                                                                        |
| unsafeHeaders       | `string[]`                      | `[]`            | For safety reasons, Modern.js does not add excessive content to SSR_DATA. Developers can use this configuration to specify the headers that need to be injected                                                                                                                                                                                                                                                                                                                                |
| loaderFailureMode   | `clientRender \| errorBoundary` | `errorBoundary` | The default configuration is `'errorBoundary'`, when an error occurs in [data loader](/en/guides/basic-features/data/data-fetch.html#data-loader-recommended), it will default to rendering the [`Error`](/guides/basic-features/routes/routes#error-handling) component of the route. When configured as `'clientRender'`, if a loader throws an error, it switch to client-side rendering，you can use it with [Client Loader](/en/guides/basic-features/data/data-fetch.html#client-loader) |
| preloadRouteScripts | `boolean`                       | `true`          | Only works for streaming rendering. By default, `<link rel="preload" as="script">` is output in the HTML head for the routes matched by the request, so the JS of the route components downloads in parallel with the entry JS. Only the matched routes are included, not the modules lazy loaded inside the route components. Set to `false` to disable it                                                                                                                                    |
| earlyHints          | `boolean`                       | `false`         | Send a `103 Early Hints` response before the data loaders run, with `Link` headers that preload the scripts and stylesheets of the HTML template and the JS and CSS of the routes matched by the request. Only works on the Node.js runtime, see [Early Hints](#early-hints)                                                                                                                                                                                                                   |

```ts title="modern.config.ts"
export default defineConfig({
  server: {
    ssr: {
      forceCSR: true,
      mode: 'stream',
      unsafeHeaders: ['User-Agent'],
    },
  },
});
```

### Early Hints

When `earlyHints` is enabled, the server sends a `103 Early Hints` response before running the data loaders, so the browser starts downloading the first screen assets while the server waits for the loaders. The hinted assets are:

- the `<script src>` and `<link rel="stylesheet">` of the HTML template.
- the JS and CSS of the nested routes matched by the request URL. Only the URL is used for matching, no loader runs.

```ts title="modern.config.ts"
export default defineConfig({
  server: {
    ssr: {
      earlyHints: true,
    },
  },
});
```

Notes:

- `103` does not commit the final status code. Redirects and error status codes from loaders still work, and on a redirect the early downloaded assets are wasted.
- It only works on the Node.js runtime, and is skipped when the runtime has no `writeEarlyHints`.
- Browsers only handle `103` on HTTP/2 and above. If a CDN, gateway or reverse proxy sits in front of the app, check that it forwards `103` to the browser.
- The gain is about the duration of the loaders, and at most the download time of the first screen assets. When the loaders or the network are fast, there is little gain.

### Active Fallback

In a production environment, there are scenarios where it is necessary to actively fallback an SSR project to CSR. Examples include

1. When the SSR fails, a fallback to the CSR is required to ensure product availability.

2. When the SSR is working normally, but there are rendering failures during csr, debugging is required.

3. When the SSR server is under heavy load, it may be necessary to fallback some traffic directly to the CSR to avoid service downtime.

By configuring `server.ssr.forceCSR` to `true` in the project, you can control this behavior through query strings or request headers.

For example, in a custom Web Server middleware, you can actively fallback when traffic exceeds a certain threshold:

```ts title="server/modern.server.ts"
import {
  defineServerConfig,
  type MiddlewareHandler,
} from '@modern-js/server-runtime';

export const handler: MiddlewareHandler = async (c, next) => {
  if (condition) {
    c.set('forceCSR', '1');
  }
  await next();
};

export default defineServerConfig({
  middlewares: [
    {
      name: 'request-middleware',
      handler,
    },
  ],
});
```
