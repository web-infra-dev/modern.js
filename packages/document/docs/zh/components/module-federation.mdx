模块联邦（Module Federation，简称 MF）是一种让多个 JavaScript 应用可以共享代码和资源的技术方案。它类似于服务端的微服务架构，允许你将大型应用拆分成多个独立的小应用，这些小应用可以独立开发、测试和部署，同时还能在运行时动态加载其他应用的模块。

使用模块联邦可以解决多个前端应用之间代码重复的问题。传统方式下，如果多个应用需要使用相同的组件或工具函数，需要在每个应用中重复安装这些代码，导致代码重复、维护成本高、应用体积变大。使用模块联邦后，你可以将公共代码放在一个应用中，其他应用按需动态加载，实现代码共享，减少重复。

Module Federation 2.0 支持 [Rspack](https://rspack.rs/) 构建工具，并提供了动态类型提示、Manifest、Federation Runtime、运行时插件系统和 Chrome Devtools 等增强功能，提供更好的开发体验和调试能力。你可以访问 [Module Federation 官方文档](https://module-federation.io/zh/index.html) 了解更多信息。

Modern.js 提供了一个 Module Federation 的示例项目，请参考 [module-federation-examples - modernjs](https://github.com/module-federation/module-federation-examples/tree/db5bdbeee56f779999a2c591fc553eb94eb20b36/modernjs)。

## 内置接入

Modern.js 会在应用目录检测 `module-federation.config.ts`，存在该文件时自动启用 Module Federation。无需安装或手动注册 Modern.js MF 插件，仍需安装 MF 引擎：

```bash
pnpm add @module-federation/enhanced@0.0.0-feat-bridge-route-navigation-20261028125233
```

统一 React 消费 API 从 `@modern-js/runtime/mf` 导入，Modern 管理其 Bridge 依赖。用户仍需安装支持该 API 与 expose 协议元信息的 Enhanced 版本。现有 Bridge 直接导入方式继续保留。

通用 MF 配置继续放在原文件中：

{/* prettier-ignore */}
```ts title="module-federation.config.ts"
import { createModuleFederationConfig } from '@module-federation/enhanced'

export default createModuleFederationConfig({
  name: 'host',
  remotes: {
    remote: 'remote@http://localhost:3001/mf-manifest.json',
  },
})
```

在 `modern.config.ts` 中注册 `appTools()` 即可。内置适配器会接入 CSR/SSR 构建、双端 manifest、SSR 数据获取、开发态远端更新以及服务端资源服务。

适配器为浏览器和服务端构建默认设置顶层 `shareStrategy: 'loaded-first'`。可在 `module-federation.config.ts` 中显式设置 `shareStrategy` 覆盖默认值。各 shared 项由 MF runtime 继承该默认策略，无需额外的策略运行时插件。

### moduleFederation

| 配置    | 行为                                 |
| ------- | ------------------------------------ |
| 不配置  | 根据默认 MF 配置文件是否存在决定启用 |
| `false` | 禁用内置 MF，可继续使用旧插件        |
| `true`  | 启用并读取默认文件，文件不存在时报错 |
| 对象    | 启用并设置框架适配选项               |

{/* prettier-ignore */}
```ts title="modern.config.ts"
import { appTools, defineConfig } from '@modern-js/app-tools'

export default defineConfig({
  moduleFederation: {
    fetchServerQuery: { source: 'host' },
  },
  plugins: [appTools()],
})
```

对象接受旧插件的以下选项：

| 选项                         | 说明                                                                 |
| ---------------------------- | -------------------------------------------------------------------- |
| `config`                     | 内联通用 MF 配置，优先于配置文件                                     |
| `configPath`                 | 自定义 MF 配置路径，相对应用目录解析                                 |
| `ssr`                        | 是否接入 MF SSR，默认跟随 `server.ssr`，也可设置 `{ distOutputDir }` |
| `fetchServerQuery`           | 客户端调用远端服务端数据函数时附加的 query                           |
| `autoOptimization`           | 自动设置双端 optimization target，默认开启，保留显式 target          |
| `secondarySharedTreeShaking` | 保留旧插件开关兼容，默认关闭                                         |

`server.ssr` 继续控制 Modern 应用自身的 SSR。通用的 `exposes`、`shared`、`runtimePlugins`、`dts` 和 manifest 配置仍放在 MF 配置文件中。

### 从旧插件迁移

移除 `@module-federation/modern-js-v3` 的插件注册及依赖，安装 `@module-federation/enhanced`。将配置辅助函数改从 enhanced 导入，将运行时 API 改从 `@module-federation/enhanced/runtime` 导入。

现有集成也可继续直接使用 `@module-federation/bridge-react`，React 版本入口使用 `/v18`、`/v19`，数据 API 使用 `/data-fetch`，运行时插件入口使用 `/plugin`。直接导入这些 API 时，应安装与 enhanced 相同预览版本的 bridge-react，无需额外声明 runtime 或 runtime-core 应用依赖。

渐进迁移时可以保留旧插件，同时显式设置 `moduleFederation: false`。存在 MF 配置文件时会自动启用内置适配器，因此只保留旧注册而未关闭内置能力会报错。内置 MF 与旧插件同时启用时始终报错，也会检测通过其他插件的 `usePlugins` 注册的旧插件。

### 统一 React 消费

{/* prettier-ignore */}
```tsx
import { createReactRemote, ReactRemote } from '@modern-js/runtime/mf'

const Card = createReactRemote<{ label: string }>({
  remote: 'remote/Card',
  loading: <span>Loading</span>,
  fallback: ({ error, retry }) => <button onClick={retry}>{error.message}</button>,
})

<Card label="Example" />
<ReactRemote remote="remote/Card" props={{ label: 'Example' }} />
```

`remote` 支持三类输入：注册的 `alias/Expose` 字符串、调用 MF `loadRemote` 的函数，以及返回已加载 MF 模块或其组件导出的函数。函数可以同步或异步返回，工厂与声明式 API 使用相同的行为。

{/* prettier-ignore */}
```tsx
import { loadRemote } from '@module-federation/enhanced/runtime'
import Shop, * as ShopModule from 'shop/Card'
import { createReactRemote, ReactRemote } from '@modern-js/runtime/mf'

const ById = createReactRemote({ remote: 'shop/Card' })
const ByLoader = createReactRemote({
  remote: () => loadRemote('shop/Card'),
})
const loadShop = () => ShopModule
const ByModule = createReactRemote({ remote: loadShop })
const ByComponent = createReactRemote({ remote: async () => Shop })

<ReactRemote remote={loadShop} props={{ label: 'Example' }} />
```

函数输入始终通过 thunk 传递，即 `remote: () => Shop`。返回值须来自 MF 的加载链路或静态远程 import，框架使用已有来源信息识别组件和 Bridge 协议，不要求用户添加模块标记。直接传组件函数或模块对象不是上述输入形式。预加载组件导出的来源识别由配套版本的消费者 Runtime 提供，不要求生产者重新构建或添加新标记。

声明式 `ReactRemote` 的函数输入应保持引用稳定，可像上例一样定义在模块作用域，或使用 `useCallback`。仅更新业务 props 时复用同一个函数。更换函数引用会被视为新的加载来源，并重置该消费实例的加载和组件状态。

预加载结果须来自消费入口使用的同一个 Runtime 实例。如果同一组件引用对应多个 expose 或版本，自动识别会报歧义错误，可改用字符串指定来源。旧 Runtime 仍可通过带有 MF 身份的模块命名空间兼容，预加载默认导出的识别需要配套的新 Runtime。

启用并消费 MF 生成的类型映射后，字符串字面量可推导 expose 的 props。函数输入从返回模块或组件的类型推导 props，`exportName` 只接受对应模块中的可渲染导出。两种工厂和 `ReactRemote` 使用同一套类型约束。动态字符串或缺少远端类型时，仍可显式指定业务 props，例如 `createReactRemote<{ label: string }>(...)`。

框架从 manifest 的 expose 协议选择适配器。普通组件进入 Host React 树，保留现有 SSR、水合和数据加载能力。由 `createBridgeComponent` 默认导出的 provider 会被构建标记为 `render: 'bridge'`、`isService: false`，在客户端使用生产者的独立 Root。每次挂载单独管理 provider，props 更新复用 Root，卸载时销毁。

生产者仍使用标准 exposes。框架识别 `createBridgeComponent` 的导入绑定、别名与静态 re-export，不执行业务代码探测类型。默认导出应可静态分析，复杂包装、动态选项和元信息冲突会产生构建诊断。

`exportName` 默认 `default`，支持普通组件具名导出。无协议的旧组件继续走普通组件路径，旧 Bridge 可显式设置 `render: 'bridge'`。可靠元信息与提示冲突时报错。通用注册和加载 API 继续从 `@module-federation/enhanced/runtime` 导入。

上述三类输入都支持普通组件 SSR，前提是函数及其加载的模块能够在 Node 中执行。普通组件继续使用相同的数据加载、资源输出和水合链路。`noSSR: true` 在服务端输出 loading 占位，并将函数调用和组件渲染留到客户端。已经在消费 API 之外执行的静态 import 或预加载不会被 `noSSR` 撤销。

本版本的 Bridge 在服务端只输出占位，客户端再创建 provider 和独立 Root。函数输入在服务端可能需要先加载模块以识别其协议，但不会因此执行 Bridge 渲染。字符串输入可以先读取元信息选中 Bridge 占位，无需加载 expose。Bridge SSR、Service App 与 `updateRemotes` 不属于本次能力。重试会重新调用失败的输入函数并重建失败实例，不保证重新下载已经缓存的 MF 模块或重新执行业务数据函数。

Modern 默认关闭 MF 引擎根据 bridge-react 依赖自动设置路由别名的行为，路由由 Modern 管理。显式配置 bridge.enableBridgeRouter 时保留用户选项。

## 导出 Modern 路由范围

在独立的 expose 文件中使用 `createRoot({ route })`，将返回的 ModernRoot 作为 `createBridgeComponent` 的 `rootComponent`：

{/* prettier-ignore */}
```tsx title="src/export-product.tsx"
import '@modern-js/runtime/registry/index'
import { createRoot } from '@modern-js/runtime/react'
import { render } from '@modern-js/runtime/browser'
import { createBridgeComponent } from '@modern-js/runtime/mf'

const ModernRoot = createRoot({ route: '/product' })

export default createBridgeComponent({
  rootComponent: ModernRoot,
  render: (Component, dom) => render(Component, dom),
})
```

将该文件加入 MF 配置的 `exposes`。registry 仍由用户显式导入，多入口使用各自的 registry，例如 `@modern-js/runtime/registry/admin`。

`route` 是生产者的固定路由定义路径。构建时保留该节点全部子路由，以及祖先 Layout、Loader、错误边界和必要的 index、无路径包装，移除无关兄弟分支。`route` 只选择导出内容。构建器为该导出生成应用局部路由，保留 route ID，生产者单独运行的路由表不变。选区路径不会成为导出应用的 basename。选中的内容作为一个应用交给消费者，挂载方式与导出完整应用一致。消费者可通过下文的 Modern 路由消费入口自动计算 basename 并同步导航。

省略 `route` 或调用 `createRoot()` 时导出对应 registry 的整应用。`createRoot(UserApp)` 的组件调用继续兼容。不同导出使用独立路由定义，每次挂载使用独立的 memory Router 和运行时上下文，更新 props 保留页面状态，卸载后重新挂载会创建新实例。

选区在生成页面 import 之前完成。范围出口不会因为路由配置引入无关页面，但同次构建中的整应用入口、其他 exposes 或业务模块直接 import 的页面仍可能出现在 dist 中。

首版要求 registry 导入、`createRoot` 调用和默认导出的 `createBridgeComponent` provider 在同一个 expose 定义文件中，每个文件定义一个应用 Root。支持导入别名、字面量和可解析的局部常量。路径不存在、包含动态参数或通配符、存在独立同路径分支、无法静态解析的选项都会产生构建错误。固定范围内部的动态子路由允许保留。

显式范围使用构建期路由图，不能通过 `runtime.router.createRoutes` 替换它，运行时路由 hooks 也不能改变选区拓扑。RSC 范围导出暂不支持。

服务端 Loader 继续使用 Modern 数据接口，请求指向生产者资源配置的 origin，并保留入口 base 和原路由路径。部署时该 origin 需要提供对应数据接口，跨源访问需要生产者显式配置 CORS 或通过同源代理提供接口。仅部署静态资源的 CDN 不会自动获得 Loader 服务。Bridge 在宿主服务端仍只输出占位，本能力不包含 Bridge SSR。

## 挂载到 Modern 路由

在承载远程应用的通配路由中使用 `createModernReactRemote`：

{/* prettier-ignore */}
```tsx title="src/routes/stores/[storeId]/inventory/$.tsx"
import { createModernReactRemote } from '@modern-js/runtime/mf'

export default createModernReactRemote({
  remote: 'shop/Product',
})
```

它在组件渲染时读取当前局部路由匹配，自动计算挂载 basename，并同步 Host 与远程应用的导航。Host Router basename 为 `/admin` 时，访问 `/admin/stores/100/inventory/detail/42?tab=stock#summary` 得到挂载前缀 `/admin/stores/100/inventory`。动态参数使用当前实际匹配值，无路径 Layout 和 index 不增加路径段，通配符匹配的尾部不计入前缀。用户仍需为远程子路径配置通配路由。

`useRemoteBasename()` 提供同一计算能力。显式传入的 basename 优先于自动计算，basename 是包含 Host Router basename 的完整路径前缀：

{/* prettier-ignore */}
```tsx
import { ReactRemote, useRemoteBasename } from '@modern-js/runtime/mf'

export default function Page() {
  const basename = useRemoteBasename()
  return <ReactRemote remote="shop/Product" basename={basename} />
}
```

从 `@modern-js/runtime/mf` 导入的普通 `createReactRemote` 和 `ReactRemote` 不会因位于路由组件内部而自动接管 URL。不传 basename 的应用导出继续使用独立 memory 导航，适合 Dashboard 卡片和同一导出的多个实例。业务 props 与 basename、navigation、memoryRoute 控制参数分开传递。props、地址和动态挂载参数更新复用现有 Root，卸载释放该实例订阅和 Loader 请求，重试不会复用已失败实例。

### 生产者的路由责任

`createRoot({ route: '/product' })` 只决定导出哪个应用内容，挂载路径由消费者决定。它不设置生产者 basename，也不改变生产者原应用的路由行为。

例如，导出 `/product` 范围后，应用内部的详情路由和 `useLocation().pathname` 为 `/detail/42`。消费者挂到 `/inventory` 后，浏览器地址为 `/inventory/detail/42`。导航只添加或移除消费者的 basename，不还原 `/product`。消费者无需再传选区路径，manifest 和 Snapshot 也不新增路径字段。祖先 Layout、Loader 和页面状态继续保留。

生产者单独运行时仍使用原地址 `/product/detail/42`。服务端 Loader 仍请求生产者原数据地址，这与应用内部导航路径分开处理。独立 memory 应用的 `memoryRoute.entryPath` 也使用局部路径，例如 `/detail/42?tab=stock`。框架不改写业务源码。

可复用的生产者应优先使用相对 Link、navigate 和 redirect，并自行适配依赖 basename 或 pathname 的逻辑。相对导航解决地址生成，不能替代路由表自身的匹配。框架不会扫描或改写写死的绝对路径，无法匹配的路径按正常路由错误处理。

### 其他 Router 与兼容边界

不用 Modern Router 时，可以给 `createReactRemote` 或 `ReactRemote` 手动传 basename。普通浏览器 history 场景监听 popstate，并将远程 push、replace 和历史移动写入浏览器。自定义 Router 若通过 pushState 导航却不发布位置变化，需要提供 `navigation` Adapter 的 `getLocation`、`subscribe` 和 `navigate`，仅传路径字符串不能订阅任意 Router。

CSR 宿主中的 Modern 自带 Hash Router 使用 Router 的逻辑路径计算和导航，不将带 `#` 的 href 作为 pathname 拼接。其他 Hash Router 需要对应 Adapter。fragment 不会发送给服务端，因此 Hash 深层入口在客户端确定，本版不支持 Hash Router 宿主的 SSR 水合。

旧 Bridge 产物继续使用其原有 Router 行为，缺少新 navigation 集成时不会自动获得双向同步。无协议标记的旧产物仍需 `render: 'bridge'`。普通组件继续进入 Host React 树。Bridge 在 SSR Host 中仍输出占位，浏览器挂载后同步导航，本能力不实现 Bridge SSR、Service App 或远程版本替换。
