# server.compress

- **类型：** `boolean | object`
- **默认值：** 内置 Node.js 生产服务器为 `true`

使用 Brotli 或 gzip 压缩生产服务器提供的静态文件，包括 `static/` 中的构建产物，以及来自 `config/public`、`config/upload` 和 `server.publicDir` 的文件。

SSR 页面、BFF 响应以及自定义中间件的响应不会被压缩。如果它们的编码取决于请求头 `Accept-Encoding`，每个响应都需要带上 `Vary: Accept-Encoding` 头。如需压缩它们，可以使用反向代理或自定义中间件。

内置 Node.js 生产服务器（`modern serve` 和 `node .output/index`）默认开启压缩，开发服务器不受影响。其他运行环境（例如 Netlify Functions）通常会在边缘节点压缩响应，因此默认不开启，可以将 `compress` 设置为 `true` 来开启。

服务器会根据请求头 `Accept-Encoding`，从 `encodings` 中选择客户端支持的第一个编码。无论是否被压缩，可压缩的文件都会带上 `Vary: Accept-Encoding` 头，以便缓存区分两种版本。以下情况文件会原样返回，并且不带 `Vary`：

- 响应已经包含 `Content-Encoding` 或 `Content-Range` 头，例如已被自定义中间件压缩
- 文件的内容类型不可压缩，例如图片
- 文件小于 `threshold`
- 响应包含 `Cache-Control: no-transform` 头
- 响应体已被自定义中间件替换

`HEAD` 请求的响应和 `304 Not Modified` 响应不会被压缩，但会带上同样的 `Vary` 头。

每个文件只会压缩一次，之后直接从内存中返回。压缩后的内容与原始内容的字节不同，因此压缩文件上的强 `ETag`（例如通过 `server.routes` 设置）会被改为弱 `ETag`。

### 关闭压缩

如果由反向代理或 CDN 负责压缩，可以关闭该功能：

```ts title="modern.config.ts"
export default defineConfig({
  server: {
    compress: false,
  },
});
```

### 配置项

| 名称        | 类型                    | 默认值           | 说明                               |
| ----------- | ----------------------- | ---------------- | ---------------------------------- |
| `threshold` | `number`                | `1024`           | 小于该大小（字节）的文件不会被压缩 |
| `encodings` | `Array<'br' \| 'gzip'>` | `['br', 'gzip']` | 支持的编码，按服务器优先级排序     |

```ts title="modern.config.ts"
export default defineConfig({
  server: {
    compress: {
      threshold: 2048,
      encodings: ['gzip'],
    },
  },
});
```
