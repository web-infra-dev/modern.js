# server.tsconfigPath

- **类型：** `string`
- **默认值：** `undefined`（按下方优先级自动解析）

指定服务端 TypeScript 相关流程使用的 tsconfig 文件。

该配置会影响：

- BFF / API 编译（`@modern-js/plugin-bff`，`api/` 目录）
- 自定义 Server 编译（`server/` 目录，以及随之编译的 `shared/` 目录）
- 运行时 ts-node 注册（如 SSR、`config/` 目录下的 `.ts` 文件）

## 解析优先级

服务端 tsconfig 按以下顺序解析，命中即停止：

1. **显式配置**：`server.tsconfigPath`（相对 `appDirectory` 解析，也支持绝对路径）。
2. **约定文件**：`<appDirectory>/tsconfig.server.json` 存在时自动使用，无需任何配置。
3. **回退**：`<appDirectory>/tsconfig.json`。

前两种情况下，文件内容会被原样使用，框架不会改写任何编译选项。

## 回退时的改写规则

`@modern-js/tsconfig/base` 是面向打包器的配置（`module: ESNext`、`moduleResolution: bundler`）。如果服务端编译直接使用它，产物会是 ES Module，而 `package.json` 没有 `"type": "module"` 的项目无法 `require()` 这些产物。

因此**只在回退到 `tsconfig.json`** 时，框架会做一次判断：

| 条件 | 行为 |
| --- | --- |
| 解析 `extends` 后的 `module` 为 ES Module 取值（`es2015` / `es6` / `es2020` / `es2022` / `esnext` / `preserve`，不区分大小写），且 `package.json#type` 不是 `module` | 以 `module: NodeNext` 与 `moduleResolution: NodeNext` 编译服务端代码，并打印一次警告，建议添加 `tsconfig.server.json` |
| `module` 为 `commonjs` / `node16` / `nodenext` 等 | 不改写 |
| `package.json#type` 为 `module` | 不改写（ESNext 产物正是 ESM 项目需要的，框架会为相对导入补全 `.js` 后缀） |

`module` 与 `moduleResolution` 总是一起改写：TypeScript 不允许只改其中一个（TS5095 / TS5109 / TS5110）。

## 推荐布局

保留一份主配置 `tsconfig.json`（编辑器、Rspack 别名、类型检查），再加一份只改模块选项的 `tsconfig.server.json`：

```json title="tsconfig.json"
{
  "extends": "@modern-js/tsconfig/base",
  "compilerOptions": {
    "noEmit": true,
    "types": ["node"],
    "paths": {
      "@/*": ["./src/*"],
      "@shared/*": ["./shared/*"],
      "@api/*": ["./api/lambda/*"]
    }
  },
  "include": ["src", "shared", "config", "api", "server", "modern.config.ts"]
}
```

```json title="tsconfig.server.json"
{
  "extends": ["./tsconfig.json", "@modern-js/tsconfig/server"],
  "include": ["api", "server", "shared"]
}
```

`@modern-js/tsconfig/server` 只包含四个字段：`module: NodeNext`、`moduleResolution: NodeNext`、`noEmit: false`、`declaration: false`。它出现在 `extends` 数组末尾，因此只覆盖这四个键，其余选项全部继承自 `tsconfig.json`。

有了 `tsconfig.server.json` 之后不需要再配置 `server.tsconfigPath`；只有当文件名或位置不同时才需要显式指定：

```ts title="modern.config.ts"
export default defineConfig({
  server: {
    tsconfigPath: './config/tsconfig.node.json',
  },
});
```

## 注意事项

- **`paths` 必须留在 `tsconfig.json` 中**。TypeScript 在 `extends` 合并时对 `compilerOptions` 逐键覆盖，但对 `paths` 是整体替换；在 `tsconfig.server.json` 里声明 `paths` 会丢掉主配置中的全部别名。框架读取别名时会沿 `extends` 链查找，所以服务端配置只继承即可。
- `tsconfig.server.json` 中的 `include` 只需列出服务端目录。
- ts-node 10.x 无法解析数组形式的 `extends`。Modern.js 注册 ts-node 时会自行解析整条 `extends` 链，因此 `modern dev` 不受影响；但如果你直接用 ts-node CLI 以该文件为 project 运行脚本，需要改用单个 `extends` 并把 `module: NodeNext`、`moduleResolution: NodeNext` 写在文件内。
- 如果显式配置的文件不存在，TypeScript / ts-node 会在启动时抛出错误。
- 不希望采用新布局的项目可以改为继承 `@modern-js/tsconfig/legacy`（旧版 `commonjs` + `node` 配置），但这些选项在 TypeScript 6 中已被标记为废弃。
