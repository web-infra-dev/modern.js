# server.tsconfigPath

- **类型：** `string`
- **默认值：** `undefined`（按下方优先级自动解析）

指定服务端 TypeScript 相关流程使用的 tsconfig 文件。

该配置会影响：

- BFF / API 编译（`@modern-js/plugin-bff`，`api/` 目录）
- 自定义 Server 编译（`server/` 目录，以及随之编译的 `shared/` 目录）
- 开发时直接运行服务端源码（如 SSR、`config/` 目录下的 `.ts` 文件）

服务端代码由 SWC 逐文件转译，产物格式跟随 `package.json#type`；这份 tsconfig 提供装饰器、`target`、`jsx`、`paths` 等选项，并用于类型检查：构建时框架调用项目自己的 `tsc` 命令行检查 `api/`、`server/`、`shared/`（TypeScript 5 / 6 / 7 均可），类型错误会让构建失败。框架不再依赖 TypeScript 的 JS API，也不需要安装 ts-node。

## 解析优先级

服务端 tsconfig 按以下顺序解析，命中即停止：

1. **显式配置**：`server.tsconfigPath`（相对 `appDirectory` 解析，也支持绝对路径）。
2. **约定文件**：`<appDirectory>/tsconfig.server.json` 存在时自动使用，无需任何配置。
3. **回退**：`<appDirectory>/tsconfig.json`。

前两种情况下，除了强制输出（见下文）外，文件内容原样使用。

## 回退时的改写规则

`@modern-js/tsconfig/base` 是面向打包器的配置（`module: ESNext`、`moduleResolution: bundler`）。产物格式只跟随 `package.json#type`，不受它影响；但服务端的类型检查应按 Node 的规则解析模块。

因此**只在回退到 `tsconfig.json`** 时，框架会为类型检查做一次判断：

| 条件                                                                                                                                                                 | 行为                                                                           |
| -------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| 解析 `extends` 后的 `module` 为 ES Module 取值（`es2015` / `es6` / `es2020` / `es2022` / `esnext` / `preserve`，不区分大小写），且 `package.json#type` 不是 `module` | 类型检查以 `module: NodeNext` 与 `moduleResolution: NodeNext` 进行，不打印提示 |
| `module` 为 `commonjs` / `node16` / `nodenext` 等                                                                                                                    | 不改写                                                                         |
| `package.json#type` 为 `module`                                                                                                                                      | 不改写（产物是 ESM，框架会为相对导入补全 `.js` 后缀）                          |

`module` 与 `moduleResolution` 总是一起改写：TypeScript 不允许只改其中一个（TS5095 / TS5109 / TS5110）。

## 推荐布局

保留一份主配置 `tsconfig.json`（编辑器、Rspack 别名、类型检查），再加一份只改模块选项的 `tsconfig.server.json`：

```json title="tsconfig.json"
{
  "extends": "@modern-js/tsconfig/base",
  "compilerOptions": {
    "noEmit": true,
    "types": ["@modern-js/app-tools/types"],
    "paths": {
      "@/*": ["./src/*"],
      "@shared/*": ["./shared/*"],
      "@api/*": ["./api/lambda/*"]
    }
  },
  "include": ["src", "shared", "config", "api", "server", "modern.config.ts"]
}
```

```json title="tsconfig.server.json"
{
  "extends": "./tsconfig.json",
  "compilerOptions": {
    "module": "NodeNext",
    "moduleResolution": "NodeNext",
    "noEmit": false,
    "declaration": false
  },
  "include": ["api", "server", "shared"]
}
```

这四个 `compilerOptions` 只覆盖对应的键，其余选项全部继承自 `tsconfig.json`。`@modern-js/tsconfig/server` 作为参考预设发布，内容就是这四个字段，供支持 `extends` 数组的工具（tsc >= 5.0）使用；推荐的 `tsconfig.server.json` 把它们直接写在文件内，让仍在使用 ts-node 10 的工具也能读取（它不支持 `extends` 数组）。

Modern.js 不会自动生成 `tsconfig.server.json`。存量项目可以用迁移 Skill 的脚本写入（见 [迁移存量项目](/guides/basic-features/typescript#迁移存量项目)），也可以按上面的内容手动添加。

编译 `api/`、`server/`、`shared/` 时，Modern.js 总是产出 JS（忽略 `noEmit` 与 `emitDeclarationOnly`，服务端编译本身就是产出步骤）；`declaration` 保持配置文件中的取值，开启时由同一次 `tsc` 调用生成 `.d.ts`（跨项目 BFF 依赖它），其中的别名同样改写为相对路径。

有了 `tsconfig.server.json` 之后不需要再配置 `server.tsconfigPath`；只有当文件名或位置不同时才需要显式指定：

```ts title="modern.config.ts"
export default defineConfig({
  server: {
    tsconfigPath: './config/tsconfig.node.json',
  },
});
```

## 注意事项

- **`paths` 必须留在 `tsconfig.json` 中**。TypeScript 在 `extends` 合并时对 `compilerOptions` 逐键覆盖，但对 `paths` 是整体替换；在 `tsconfig.server.json` 里声明 `paths` 会丢掉主配置中的全部别名。框架读取别名时会沿 `extends` 链查找，所以服务端配置只继承即可。
- `tsconfig.server.json` 中的 `include` 只需列出服务端目录。
- `tsconfig.server.json` 中的 `extends` 建议保持为单个字符串，兼容仍在使用 ts-node 10 的工具。
- tsconfig 中的 `"ts-node"` 配置段继续生效：`compilerOptions` 覆盖文件中的同名选项，`require` 中的模块会在服务端代码之前加载。
- 项目没有安装 `typescript` 时，服务端代码照常编译，但跳过类型检查并给出提示。
- 不希望采用新布局的项目可以改为继承 `@modern-js/tsconfig/legacy`（旧版 `commonjs` + `node` 配置），但这些选项在 TypeScript 6 中已被标记为废弃。
