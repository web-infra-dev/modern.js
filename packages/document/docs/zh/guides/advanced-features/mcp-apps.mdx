# MCP Apps

Modern.js 可以把 React 组件构建为 MCP 卡片。UI 构建与服务端通过 `ui-manifest.json` 关联，服务端直接使用官方 MCP SDK。

## 创建项目

```bash
npx @modern-js/create@latest my-mcp --template mcp-apps
# 复用本项目的 Module Federation expose
npx @modern-js/create@latest my-mf-mcp --template mcp-apps --mf
```

使用包含 MCP Apps 支持的版本。运行 `pnpm dev` 后，MCP 地址为 `/api/mcp`。

构建插件、服务端插件、服务端适配器和卡片运行时都由 `@modern-js/mcp-apps` 提供，分别从 `./cli`、`./server-plugin`、`./server` 和 `./react` 导入。应用需安装 peer 依赖 `react`、`react-dom`、`@modelcontextprotocol/server` 和 `@modelcontextprotocol/ext-apps`，让卡片使用应用的 React，工具、资源注册和 HTTP 处理使用应用安装的 SDK。`@modern-js/server-runtime` 和 `@module-federation/enhanced` 是可选 peer，分别作为 BFF handler 获取请求上下文和 MF shell 运行时的默认实现。脚手架模板已声明这些依赖。

## 声明卡片

创建 `mcp-views.json`。字符串路径相对该 JSON 文件解析。对象可以引用本项目 MF 配置中已有的 expose，也可以通过 `remote` 引用已部署的远程模块，见下文。

下面用 JSONC 注释说明配置字段。实际的 `mcp-views.json` 必须是合法 JSON，使用时请移除注释。

```jsonc
{
  // 卡片名称到视图配置的映射
  "views": {
    "todos": {
      // 本地 React 组件路径，相对 mcp-views.json 解析，组件必须默认导出
      "component": "./src/components/Todos.tsx",
      // 可选的资源配置
      "resource": {
        // 自定义资源 URI，省略时自动生成 ui://app/todos
        "uri": "ui://app/todos",
        "_meta": {
          // 仅覆盖当前卡片的 UI 元数据
          "ui": {
            // 请求宿主为该卡片显示边框
            "prefersBorder": true,
          },
        },
      },
    },
    // 引用已部署的 MF 远程模块
    "stats": {
      // 远程模块暴露的名称，必须以 ./ 开头
      "expose": "./Stats",
      // 远程 MF manifest 的绝对 HTTP(S) 地址，路径必须以 .json 结尾
      "remote": "https://example.com/mf-manifest.json",
    },
  },
  // 全局 CSP 配置，应用到所有卡片
  "csp": {
    // 允许卡片连接的 API 域名
    "connectDomains": ["https://api.example.com"],
  },
}
```

工具的名称、参数、元数据和处理逻辑直接在 MCP server 中定义，通过 `_meta.ui.resourceUri` 关联 `registerUiResources` 返回的资源 URI。

在 `modern.config.ts` 中从 `@modern-js/mcp-apps/cli` 导入并加入 `mcpAppsPlugin({ views: './mcp-views.json' })`。本地卡片仅需该插件，MF 卡片还需启用 `@module-federation/modern-js-v3` 插件并开启 manifest 输出。插件读取实际 MF 构建产物，验证 expose 存在，生成项目自身构建的 shell。

插件按文件名在 web 构建产物中查找 MF manifest，默认为 `mf-manifest.json`，必须恰好匹配一个文件。shell 默认从 `@module-federation/enhanced/runtime` 导入 `createInstance`。使用其他 MF 实现时，可以通过 `mf` 参数替换：

```ts
mcpAppsPlugin({
  views: './mcp-views.json',
  mf: {
    // 构建产物中 MF manifest 的文件名
    manifestFile: 'vmok-manifest.json',
    // 从应用解析，需导出兼容的 createInstance
    runtime: '@vmok/kit/runtime',
  },
});
```

### 引用已部署的远程模块

卡片由另一个项目作为 MF 远程模块发布时，用 `remote` 指定远程模块的 manifest 地址：

```json
{
  "remote": "https://ui.example.com/mf-manifest.json",
  "views": {
    "todos": { "expose": "./Todos" },
    "stats": { "expose": "./Stats" }
  },
  "csp": { "resourceDomains": ["https://cdn.example.com"] }
}
```

顶层 `remote` 与 `csp` 同级，供所有 expose 视图共用。单个视图可配置 `remote` 覆盖默认值。字符串路径仍引用本地组件。顶层和视图都未配置 `remote` 时，expose 引用本项目。配置顶层 `remote` 后，同一份配置中的 expose 视图无法再引用本项目的 expose。需要混用时，不配置顶层 `remote`，只在引用远程模块的视图上配置。

- 地址必须是绝对的 HTTP(S) 地址，路径以 `.json` 结尾。不支持直接引用 `remoteEntry.js` 等非 manifest 入口
- 不需要填写远程模块的名称，运行时从 manifest 读取
- shell 在卡片打开时读取远程 manifest 并加载 expose。远程模块重新发布后，MCP 服务无需重新构建或重启。构建时不检查 expose 是否存在，缺失时卡片显示加载错误
- 本项目不需要启用 MF 插件，但需要安装 `mf.runtime` 指定的运行时。远程模块使用其他 MF 实现时，按上文设置 `mf.runtime`
- manifest 所在的 origin 会自动加入 CSP。远程模块的脚本和样式由其他域名（例如 CDN）提供时，需要在 `csp.resourceDomains` 中声明。manifest 和脚本需允许跨域访问
- 远程模块需把 React 声明为 singleton 共享依赖，与 shell 共用同一份 React
- 新增卡片或修改 `remote`、`expose` 时，仍需重新构建 MCP 服务

本地卡片以独立入口构建，不加载框架的页面运行时。`source.enableAsyncEntry` 开启时，入口通过动态 import 建立异步边界，供 MF 共享依赖完成初始化。MF 插件会自动开启该选项。未开启时直接挂载卡片，不增加额外请求。

卡片必须默认导出 React 组件。props 来自 tool 返回的 `structuredContent`，`mcpApp` 为框架保留的注入字段。

{/* prettier-ignore */}
```tsx
import type { McpViewProps } from '@modern-js/mcp-apps/react'

export default function Todos({
  todos = [],
  mcpApp,
}: McpViewProps<{ todos: string[] }>) {
  return (
    <section>
      <ul>
        {todos.map(todo => (
          <li key={todo}>{todo}</li>
        ))}
      </ul>
      <button
        onClick={() =>
          mcpApp.callServerTool({ name: 'refresh', arguments: {} })
        }
      >
        刷新
      </button>
    </section>
  )
}
```

默认包装器处理连接、主题、加载、错误、取消和 teardown。开始新一轮 tool 调用时会清空旧结果，不把输入参数合并进 props。卡片内调用 tool 返回的结果由组件自己处理，不会自动替换当前卡片数据。

## 编写服务端

创建 `api/lambda/mcp.ts`，使用官方 `McpServer`、`registerAppTool` 和 zod。UI 插件不自动挂载任何 MCP 路由。

{/* prettier-ignore */}
```ts
import { McpServer } from '@modelcontextprotocol/server'
import { registerAppTool } from '@modelcontextprotocol/ext-apps/server'
import {
  createBffHandlers,
  registerUiResources,
} from '@modern-js/mcp-apps/server'
import { z } from 'zod'

async function createServer(request: Request) {
  const server = new McpServer({ name: 'todos', version: '1.0.0' })
  const ui = await registerUiResources(server, { request })
  registerAppTool(
    server,
    'list_todos',
    {
      inputSchema: z.object({}),
      _meta: { ui: { resourceUri: ui.todos } },
    },
    async () => ({
      content: [{ type: 'text', text: 'Todo list' }],
      structuredContent: { todos: ['Read the MCP Apps guide'] },
    }),
  )
  return server
}

export const { POST, GET, DELETE } = createBffHandlers(createServer)
```

需要启用 `bffPlugin()`。适配器根据 BFF 已解析的 JSON 重建请求，返回 SDK 的原始 Response。适配器通过 `@modern-js/server-runtime` 的 `useHonoContext` 获取原始请求，基于 Modern.js 封装的框架可以通过 `createBffHandlers(createServer, { useContext })` 传入自己的实现。默认无状态 HTTP 模式由官方 SDK 处理协议和参数校验，GET、DELETE 等不支持的会话操作由 SDK 返回错误。认证与业务授权放在 HTTP 中间件或 `createServer` 中。每个请求创建独立的 server，业务数据需要持久化到外部存储。

独立 Hono 服务可通过 `app.all('/mcp', c => handle(c.req.raw))` 挂载 `createFetchHandler(createServer)`。适配器默认只允许同源浏览器请求，额外来源通过第二个参数的 `allowedOrigins` 配置。

## 清单与部署

```text
dist/
├─ mcp-apps/
│  ├─ ui-manifest.json
│  └─ ui/
│     ├─ mcp-ui-<name>-<hash>.html
│     └─ mcp-shell.html
└─ static/
   └─ mf-manifest.json
```

本地卡片文件名由卡片名生成稳定 hash，避免文件名冲突与路径注入。MF 卡片共用 shell。

清单契约为：

```json
{
  "version": 1,
  "assetBase": "request",
  "remotes": {
    "todo_ui": {
      "entry": "static/mf-manifest.json",
      "shell": "./ui/mcp-shell.html"
    }
  },
  "views": {
    "todos": {
      "html": "./ui/mcp-ui-local-25bf8e1a2393.html",
      "ui": { "prefersBorder": true }
    },
    "stats": { "remote": "todo_ui", "expose": "./Stats", "ui": {} }
  }
}
```

- `html`、`shell` 相对清单文件位置解析，也支持绝对 HTTP(S) 地址
- `entry` 相对 `assetBase` 解析，也支持绝对 HTTP(S) 地址
- `ui` 保留卡片的 CSP、permissions、domain、prefersBorder 元数据
- 清单保留可选的 `resource` 声明。未指定 URI 时，服务端生成 `ui://app/<编码后的卡片名>`，多个工具可以复用同一资源
- MF 配置在读取 resource 时注入 shell，不需要 tool result 携带框架元数据

`createBffHandlers()` 将服务端插件提供的清单路径和运行模式关联到当前请求。调用 `registerUiResources(server, { request })` 即可自动获取配置。开发使用框架的内部目录，生产使用运行时的实际输出目录。显式选项优先于注入配置。独立服务必须显式配置 `manifest` 文件路径或 HTTP(S) URL，`mode` 默认为 `production`。相对 HTML 路径以清单位置为基准解析。

清单按来源地址和环境缓存。生产环境在进程生命周期内复用，原地址更新清单后需重启进程。开发环境检查本地文件状态，文件变化后重新加载，远程清单缓存 60 秒。并发加载会合并，加载失败后允许重试。HTML 仍在读取资源时加载，请求相关的地址和 metadata 不会跨请求复用。

`output.assetPrefix` 为绝对地址时用于推导 `assetBase`。`request` 表示使用请求的公开 origin，支持经过代理清理的 `x-forwarded-proto`。子路径或外部静态资源部署可以通过 `registerUiResources` 的 `assetBase` 显式覆盖。反向代理必须保留公开 host 并清理转发头。

服务端把资源根地址加入 CSP 的 resourceDomains、connectDomains 和 baseUriDomains，把 MF entry 的 origin 加入 connectDomains 和 resourceDomains。构建时还会把绝对地址或不带协议的 `output.assetPrefix` 的 origin 加入 CSP，`//cdn.example/` 按 `https://cdn.example` 处理。其他 CDN、接口和 iframe 域名需在 `mcp-views.json` 中声明，或在配置中计算后通过 `mcpAppsPlugin({ csp })` 传入，两者都会合并到每张卡片。生产部署必须保留清单、HTML、应用静态资源和 MF 产物。

平台可以把已构建的卡片文件和 MF 地址转换为绝对地址，组合成同版本的新清单，再由独立服务端消费。未知清单版本会被拒绝。

## 打包豆包工作台 Plugin

配置 `mcpServers` 后，生产构建会在应用产物目录下生成独立的 `plugin/` 包。服务地址必须显式提供完整的 HTTP(S) 部署 URL，包含实际 MCP 路由。可以通过部署环境变量传入，框架不会从静态资源地址推断 MCP 服务地址。

```ts
mcpAppsPlugin({
  views: './mcp-views.json',
  mcpServers: {
    // 工作台通过 server: 'tasks' 引用这个服务配置键
    tasks: {
      type: 'streamable-http',
      url: 'https://app.example.com/api/mcp',
    },
  },
  plugin: {
    // 可选，相对项目根目录，默认值为 'plugin'
    directory: './plugin',
    resources: ['com.doubao'],
  },
});
```

用户在源目录中编写 `plugin.json`，例如：

```json
{
  "$schema": "https://agent-plugins.org/schemas/1.0.0/plugin.schema.json",
  "name": "tasks-workbench",
  "version": "1.0.0",
  "description": "待办工作台",
  "author": { "name": "示例开发者" },
  "extensions": {
    "com.doubao": {
      "displayName": { "zh": "待办工作台" },
      "displayDescription": { "zh": "查看和管理待办事项" },
      "icon": "./com.doubao/assets/plugin-icon.png"
    }
  }
}
```

图标文件需放在对应路径。需要定制导航时，再提供 `com.doubao/workbench/manifest.json`。工作台通过 `{ "server": "tasks", "name": "open_todos" }` 引用 Server 实际注册的工具，工具参数、元数据和 handler 仍然只在 Server 中定义。工作台配置与资源格式参见[豆包 Plugin 定制工作台协议](https://bytedance.larkoffice.com/docx/NrkgdZ25QoaMbBx0d5Fcy6kOnzm)。

默认目录结构如下，工作台配置及其资源按需提供：

```text
plugin/                         # 用户维护的源目录
├─ plugin.json
└─ com.doubao/
   ├─ assets/plugin-icon.png
   └─ workbench/
      ├─ manifest.json
      ├─ preinstall-resources.json
      ├─ assets/
      └─ web/

dist/plugin/                    # 构建生成的 Plugin 包根
├─ plugin.json                  # 原样复制
├─ mcp.json                     # 框架生成
└─ com.doubao/                  # 原样复制配置和资源
```

生成的 `dist/plugin/mcp.json` 为：

```json
{
  "$schema": "https://agent-plugins.org/schemas/1.0.0/mcp.schema.json",
  "mcpServers": {
    "tasks": {
      "type": "streamable-http",
      "url": "https://app.example.com/api/mcp"
    }
  }
}
```

打包始终复制源目录的 `plugin.json`。通过 `plugin.resources` 显式选择额外的文件或目录，路径相对源包目录，默认值为 `[]`。本例配置 `['com.doubao']`，其他宿主可配置 `['assets', 'vendor.example']`。声明的路径必须存在，不允许绝对路径、空路径段、`.` 或 `..` 路径段，也不允许选择保留的 `plugin.json` 和 `mcp.json`。资源路径及其内容不支持符号链接。不读取用户手写的 `mcp.json`。源目录不能与输出包目录重叠，包内不支持符号链接。每次成功打包都会替换 `dist/plugin/`，清理不再使用的资源。自定义应用产物目录时，Plugin 包也随之输出到该目录的 `plugin/` 下。未配置 `mcpServers` 时不生成 Plugin 包，单独配置 `plugin` 会报错。开发模式不生成部署包。

`dist/plugin/` 是插件声明与资源包，应用服务及 MCP UI 产物仍需正常部署。当前打包不会校验完整的豆包工作台协议或远程工具是否存在，也不会自动生成工作台导航、编译 `web/` 页面或添加启动结果领取逻辑。这些配置和页面需要遵循宿主协议并与 MCP Server 一同发布。

## 自定义资源元数据

每个组件视图或 expose 视图都可以配置 `resource`：

```json
{
  "views": {
    "sales-overview": {
      "component": "./src/components/SalesOverview.tsx",
      "resource": {
        "uri": "ui://app/sales-overview",
        "mimeType": "text/html;profile=mcp-app",
        "_meta": {
          "ui": {
            "availableDisplayModes": ["inline", "fullscreen"],
            "preferredDisplayMode": "inline",
            "prefersBorder": true,
            "permissions": {},
            "csp": { "connectDomains": ["https://api.example.com"] }
          },
          "vendor/custom": { "enabled": true }
        }
      }
    }
  }
}
```

`resource._meta` 接受宿主扩展字段，`ui` 内的未知字段也会保留。框架将其保存到构建 manifest，并在资源注册列表 `resources/list` 和资源内容 `resources/read` 中返回。`resource.mimeType` 覆盖 SDK 默认值。`resource.uri` 覆盖自动生成的 `ui://app/<编码后的视图名>`。工具及其元数据直接在 MCP server 中定义，通过 `_meta.ui.resourceUri` 关联注册后的资源 URI。

视图的 `resource._meta.ui` 覆盖公共 UI 默认值。四类已知 CSP 域名数组与公共配置、页面必需域名去重合并，未知 CSP 字段保持原值。显式 `permissions` 整体替代默认权限，`{}` 也生效。其他元数据值覆盖默认值，框架不解释其宿主语义。`title`、`description` 等资源声明字段交给 SDK 注册。HTML 内容由框架生成，不能配置 `text` 或 `blob`。

工具元数据放在 MCP server 的工具定义 `_meta` 中。资源元数据不会自动复制到工具或 URL 来源元数据中。`preferredDisplayMode` 等扩展字段是否生效由宿主决定，不会修改 `mcpCapabilities`、主动请求全屏或改变 SDK 握手。URL 模式仍然返回 `text/html` 页面，并使用原有宿主工具声明。

## 卡片能力声明

卡片默认声明支持 `inline` 和 `fullscreen`。本地组件模块及 MF expose 都可以导出 `mcpCapabilities`，补充能力或覆盖展示模式。

{/* prettier-ignore */}
```tsx
import type { McpCapabilities } from '@modern-js/mcp-apps/react'

export const mcpCapabilities = {
  availableDisplayModes: ['inline'],
} satisfies McpCapabilities

export default function Card() {
  return <div>My card</div>
}
```

手动使用 `createMcpView` 时，也可以通过第三个参数传入能力声明。显式的展示模式数组会替换默认值。MF 模块在初始化前加载，确保握手包含该模块的能力。声明支持全屏不会自动添加全屏按钮或切换展示模式。

## 连接已部署的服务

应用开发者构建并部署 MCP 服务后，将实际的 MCP 地址提供给用户，例如 `https://example.com/api/mcp`。用户无需克隆应用或 Modern.js 仓库，也无需在本机运行 `pnpm dev`。服务需保持运行，客户端还需支持 MCP Apps 卡片展示。

### HTTP 直连

如果客户端支持 Streamable HTTP，选择该传输类型，并将服务器地址填写为 `https://example.com/api/mcp`。鉴权信息按服务要求在客户端配置。

### 通过 STDIO 连接

如果客户端仅支持 STDIO，用户需先安装 Node.js 20 或更高版本（含 npm 和 `npx`），再配置 `modern-mcp-stdio` 桥接命令。`npx` 会下载并运行指定版本的包，无需预先安装 Modern.js。

将下面的 `<version>` 替换为包含 `modern-mcp-stdio` 功能的已发布 `@modern-js/mcp-apps` 版本，将 URL 替换为实际部署地址。应用提供方应向用户提供已验证的具体版本号。

```json
{
  "mcpServers": {
    "app": {
      "command": "npx",
      "args": [
        "-y",
        "--package=@modern-js/mcp-apps@<version>",
        "modern-mcp-stdio",
        "--url",
        "https://example.com/api/mcp"
      ]
    }
  }
}
```

如果客户端使用表单，命令填写 `npx`，参数按 `args` 数组逐项添加，每项单独一行。若客户端找不到 `npx`，命令填写用户本机的 `npx` 绝对路径。需要鉴权时，在参数末尾追加 `--header` 和 `Authorization: Bearer <token>` 两项，多个请求头可重复添加。

这里使用 `--url` 连接已部署的 HTTP 服务。`--cwd` 和本地脚本路径用于下文的开发调试，不需要提供给最终用户。桥接命令不会启动或部署应用服务。

生产环境如需将本地组件卡片打包为自包含 HTML，应用开发者应在 `mcpAppsPlugin` 中设置 `inline: true` 后构建部署。`inline: 'dev'` 仅作用于开发模式。MF 卡片仍需宿主能够访问其远程资源。

## 本机 stdio 调试

面向只支持本机 stdio 接入或限制隔离 iframe 访问本地资源的宿主（如桌面端 Agent），在 `mcpAppsPlugin` 中配置 `inline`，然后运行 `pnpm dev` 启动开发服务。

```ts
mcpAppsPlugin({
  views: './mcp-views.json',
  // 'dev' 仅在开发模式打包自包含内联 HTML，true 同时作用于开发和生产构建
  inline: 'dev',
});
```

启动 `pnpm dev` 后，终端会输出一段可直接复制到本机 MCP 连接器的配置，使用 `@modern-js/mcp-apps` 内置的轻量脚本 `modern-mcp-stdio` 将 stdio 的 JSON-RPC 转发到本地 HTTP 开发服务（例如 `http://localhost:8088/api/mcp`）：

```json
{
  "mcpServers": {
    "app": {
      "command": "node",
      "args": [
        "<app>/node_modules/@modern-js/mcp-apps/bin/modern-mcp-stdio.js",
        "--cwd",
        "<app>"
      ]
    }
  }
}
```

- **请求处理**：开发服务通过应用的 BFF 路由、自定义 Hono 中间件和服务端插件处理 HTTP 请求。需要向鉴权中间件透传请求头时，可追加 `--header "Authorization: Bearer <token>"`（可重复传多个）
- **自动端口发现**：默认连接器使用 `--cwd <项目目录>`，脚本在每次请求时读取 `node_modules/.modern-js/mcp-apps/dev-server.json` 自动定位当前开发服务地址。也可直接传入固定的 HTTP MCP URL
- **增量构建**：`inline` 模式下本地组件卡片通过独立的 watch 构建打包为单文件自包含 HTML（内联脚本、样式和导入资源，上限 5 MiB，不注入 `<base>` 或本地 CSP），修改组件后自动重编，下次读取卡片资源时生效。普通页面使用主应用的 HMR。若同一份 `mcp-views.json` 还包含 Module Federation 卡片，本地卡片走内联、MF 卡片使用 HTTP shell
- **日志输出**：开发服务的日志输出在 `pnpm dev` 终端，转发脚本的 `stdout` 仅用于 JSON-RPC。`modern dev` 未启动或重启期间，转发脚本会返回 JSON-RPC 错误而不是退出进程，待开发服务就绪后下一次调用自动恢复

入口连接的浏览器事件供非 React 消费方接收后续通知，不提供历史状态快照。宿主关闭视图时触发 `mcp-app-teardown`，关闭后忽略迟到结果和连接回调。React 消费方应使用 `useEntryMcpApp` 读取已保留的状态并订阅变化。初始状态为 `standalone`，由入口脚本启动连接后才切换为 `connecting`。在 iframe 中嵌入页面会触发握手尝试，不代表已经确认父页面是 MCP 宿主。

应用同时需要普通 iframe 嵌入时，可设置 `mcpAppsPlugin({ entryAutoConnect: false })` 禁用自动注入的握手。在应用接入逻辑明确选择 MCP 模式时，调用 `@modern-js/mcp-apps/react` 导出的 `connectEntryMcpApp()`。重复调用复用当前连接，顶层页面和服务端调用不建立连接。连接失败后释放 App 实例，可再次显式调用重试。宿主身份通过 SDK 握手确认，不能仅凭 iframe 判断。
