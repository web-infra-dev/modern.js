# MCP Apps

Modern.js 可以把 React 组件构建为 MCP 卡片。UI 构建与服务端通过 `ui-manifest.json` 关联，服务端直接使用官方 MCP SDK。

## 创建项目

```bash
npx @modern-js/create@latest my-mcp --template mcp-apps
# 复用本项目的 Module Federation expose
npx @modern-js/create@latest my-mf-mcp --template mcp-apps --mf
# 仅创建服务端
npx @modern-js/create@latest my-server --template mcp-server
```

使用包含 MCP Apps 支持的版本。运行 `pnpm dev` 后，MCP 地址为 `/api/mcp`，UI 项目的调试器地址为 `/mcp/inspector`。

## 声明卡片

创建 `mcp-views.json`。字符串路径相对该 JSON 文件解析。对象仅支持引用本项目 MF 配置中已有的 expose。

```json
{
  "views": {
    "todos": "./src/components/Todos.tsx",
    "stats": { "expose": "./Stats" }
  },
  "csp": { "resourceDomains": [], "connectDomains": [] },
  "prefersBorder": true
}
```

在 `modern.config.ts` 中加入 `mcpAppsPlugin({ views: './mcp-views.json' })`。本地卡片仅需该插件，MF 卡片还需启用 `@module-federation/modern-js-v3` 插件并开启 manifest 输出。插件读取实际 MF 构建产物，验证 expose 存在，生成项目自身构建的 shell。

卡片必须默认导出 React 组件。props 来自 tool 返回的 `structuredContent`，`mcpApp` 为框架保留的注入字段。

{/* prettier-ignore */}
```tsx
import type { McpViewProps } from '@modern-js/mcp-apps/react'

export default function Todos({
  todos = [],
  mcpApp,
}: McpViewProps<{ todos: string[] }>) {
  return (
    <section>
      <ul>
        {todos.map(todo => (
          <li key={todo}>{todo}</li>
        ))}
      </ul>
      <button
        onClick={() =>
          mcpApp.callServerTool({ name: 'refresh', arguments: {} })
        }
      >
        刷新
      </button>
    </section>
  )
}
```

默认包装器处理连接、主题、加载、错误、取消和 teardown。开始新一轮 tool 调用时会清空旧结果，不把输入参数合并进 props。卡片内调用 tool 返回的结果由组件自己处理，不会自动替换当前卡片数据。

## 编写服务端

创建 `api/lambda/mcp.ts`，使用官方 `McpServer`、`registerAppTool` 和 zod。UI 插件不自动挂载任何 MCP 路由。

{/* prettier-ignore */}
```ts
import { McpServer } from '@modelcontextprotocol/server'
import { registerAppTool } from '@modelcontextprotocol/ext-apps/server'
import {
  createBffHandlers,
  registerUiResources,
} from '@modern-js/mcp-apps/server'
import { z } from 'zod'

async function createServer(request: Request) {
  const server = new McpServer({ name: 'todos', version: '1.0.0' })
  const ui = await registerUiResources(server, { request })
  registerAppTool(
    server,
    'list_todos',
    {
      inputSchema: z.object({}),
      _meta: { ui: { resourceUri: ui.todos } },
    },
    async () => ({
      content: [{ type: 'text', text: 'Todo list' }],
      structuredContent: { todos: ['Read the MCP Apps guide'] },
    }),
  )
  return server
}

export const { POST, GET, DELETE } = createBffHandlers(createServer)
```

需要启用 `bffPlugin()`。适配器根据 BFF 已解析的 JSON 重建请求，返回 SDK 的原始 Response。默认无状态 HTTP 模式由官方 SDK 处理协议和参数校验，GET、DELETE 等不支持的会话操作由 SDK 返回错误。认证与业务授权放在 HTTP 中间件或 `createServer` 中。每个请求创建独立的 server，业务数据需要持久化到外部存储。

独立 Hono 服务可通过 `app.all('/mcp', c => handle(c.req.raw))` 挂载 `createFetchHandler(createServer)`。适配器默认只允许同源浏览器请求，额外来源通过第二个参数的 `allowedOrigins` 配置。

## 清单与部署

```text
dist/
├─ mcp-apps/
│  ├─ ui-manifest.json
│  └─ ui/
│     ├─ mcp-ui-<name>-<hash>.html
│     └─ mcp-shell.html
└─ static/
   └─ mf-manifest.json
```

本地卡片文件名由卡片名生成稳定 hash，避免文件名冲突与路径注入。MF 卡片共用 shell。

清单契约为：

```json
{
  "version": 1,
  "assetBase": "request",
  "remotes": {
    "todo_ui": {
      "entry": "static/mf-manifest.json",
      "shell": "./ui/mcp-shell.html"
    }
  },
  "views": {
    "todos": {
      "html": "./ui/mcp-ui-local-25bf8e1a2393.html",
      "ui": { "prefersBorder": true }
    },
    "stats": { "remote": "todo_ui", "expose": "./Stats", "ui": {} }
  }
}
```

- `html`、`shell` 相对清单文件位置解析，也支持绝对 HTTP(S) 地址
- `entry` 相对 `assetBase` 解析，也支持绝对 HTTP(S) 地址
- `ui` 保留卡片的 CSP、permissions、domain、prefersBorder 元数据
- 清单不记录 tool 或 resource URI，服务端生成 `ui://app/<编码后的卡片名>`，多个 tool 可以复用同一 URI
- MF 配置在读取 resource 时注入 shell，不需要 tool result 携带框架元数据

`registerUiResources()` 内部异步加载清单。生产默认读取 `dist/mcp-apps/ui-manifest.json`，开发默认读取 `node_modules/.modern-js/mcp-apps/ui-manifest.json`。自定义构建目录或部署到独立服务时，通过 `manifest` 选项传入文件路径或 HTTP(S) URL，相对 HTML 路径以该清单位置为基准解析。

`output.assetPrefix` 为绝对地址时用于推导 `assetBase`。`request` 表示使用请求的公开 origin，支持经过代理清理的 `x-forwarded-proto`。子路径或外部静态资源部署可以通过 `registerUiResources` 的 `assetBase` 显式覆盖。反向代理必须保留公开 host 并清理转发头。

服务端把资源根地址加入 CSP 的 resourceDomains、connectDomains 和 baseUriDomains，把 MF entry 的 origin 加入 connectDomains 和 resourceDomains。其他 CDN、接口和 iframe 域名需显式声明。生产部署必须保留清单、HTML、应用静态资源和 MF 产物，调试器仅在开发时构建。

平台可以把已构建的卡片文件和 MF 地址转换为绝对地址，组合成同版本的新清单，再由独立服务端消费。未知清单版本会被拒绝。
