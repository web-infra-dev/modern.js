# 构建与部署

`modern build` 由 MCP Apps 插件调用服务端编译器，将根目录定义编译到 `dist/mcp_apps.js`，静态导入的 handler 按相对路径输出。`.mts`、`.cts` 定义分别输出 `.mjs`、`.cjs`。
`modern serve` 只使用这些产物。`modern deploy` 生成可移动的 `.output/`，通过
`node .output/index.js` 启动，无须原源码目录。

默认 UI HTML 位于 `dist/mcp-apps/ui/`；必须同时部署应用静态资源或设置资源 CDN。
资源地址默认以公开 MCP origin 为基准，也可配置 `dev.assetPrefix` / `output.assetPrefix`。也可用 `view.html` 指定独立 HTTPS HTML URL，由服务端读取，并用 `view.csp` 声明其网络权限。MF 模式使用 MF 原有产物独立发布。生产定义可通过环境变量设置远程资源地址，
但 local handler 模块集合需要与构建时一致。运行时读取的独立文件、原生 addon
等额外资产仍由应用管理部署。

核心包可直接接收应用导入的 definition：`createMcpHandler(definition)`。
服务端定义和工具函数使用应用的服务端编译器；纯 `mcp-server` 模板仍通过手写 BFF 入口输出到 `dist/api/`。

当前不提供持久 MCP 会话、恢复 SSE 或跨请求取消。标准 MF 已验证，各目标产品宿主应分别验收。

## Hono 独立部署

```ts
import path from 'node:path';
import { Hono } from 'hono';
import { mcpApps } from '@modern-js/mcp-apps/hono';
import { loadMcpAppsConfig, bindUiResources } from '@modern-js/mcp-apps/server';

const root = path.resolve('application');
const definition = await loadMcpAppsConfig(path.join(root, 'mcp_apps.js'));
const app = new Hono();
app.all(
  '/mcp',
  mcpApps({
    definition: bindUiResources(definition, {
      directory: path.join(root, 'mcp-apps/ui'),
      assetBase: 'request',
    }),
  }),
);
```

部署编译后的定义、导入的 handler、`dist/mcp-apps/` 资源及应用静态文件，并安装 handler 使用的外部依赖。
该适配器不监听端口，鉴权、监听和部署由用户的 Hono 应用管理；Modern.js 默认通过 BFF 自动挂载 MCP 入口。

BFF TypeScript 开发依赖 `ts-node`（`^10.9.2`），模板已添加到 devDependencies。
ESM 项目需同时设置 package.json 的 `"type": "module"`，以及 TypeScript 的
`module: "esnext"` 和 `moduleResolution: "bundler"`。

MF 模板不再生成 `server/modern.server.ts`。使用远程工具时，插件为本应用的 `/static/*` 公共资源处理 CORS 和 OPTIONS 预检。本地 MF 构建会额外记录实际输出的资产文件，自定义目录中的 manifest 和 chunks 也可由生产服务读取，并处理对应的跨域预检。该规则不扩展到未记录的文件，`/mcp` 不受该策略影响。若 manifest 和 chunks 部署在独立 CDN，需要在 CDN 配置相应的跨域响应。

独立部署本地视图时，将完整 `dist/` 复制到上例的 `application/`，保留 `package.json` 的名称、版本和模块类型，以及所有导入模块的相对路径。通过静态服务提供 `/static/*`，或将其发布到构建时配置的资源 CDN。适配器只提供 MCP 路由，不提供静态资源服务。

本应用的 MF remote 由 Modern.js 插件读取构建产物后绑定。独立 Hono 不包含此发现逻辑，应在定义中显式配置 `remotes[].baseUrl` 和 CSP。Modern.js 内的 MF 公开开发地址使用 `dev.assetPrefix`，生产资源地址使用 `output.assetPrefix`。manifest 的 publicPath 决定实际加载地址。

仅构建 UI 并接入自建 MCP Server，参见[接入自建 MCP Server](./custom-server)。
