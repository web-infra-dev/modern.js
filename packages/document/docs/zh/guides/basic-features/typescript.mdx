# TypeScript 配置

Modern.js 通过 `@modern-js/tsconfig` 提供共享的 TypeScript 预设。一个项目通常只需要两份文件：主配置 `tsconfig.json`，以及只在有服务端代码时才需要的 `tsconfig.server.json`。

## 预设

| 预设 | 用途 |
| --- | --- |
| `@modern-js/tsconfig/base` | 主配置。`module: ESNext`、`moduleResolution: bundler`、`jsx: react-jsx`、`target: ES2022`、`strict`、`isolatedModules`。供编辑器、Rspack 别名解析与类型检查使用。 |
| `@modern-js/tsconfig/server` | 参考预设，内容是四个服务端产物覆盖项：`module: NodeNext`、`moduleResolution: NodeNext`、`noEmit: false`、`declaration: false`。供支持 `extends` 数组的工具（tsc >= 5.0）使用；推荐的 `tsconfig.server.json` 直接写入同样的四个字段。 |
| `@modern-js/tsconfig/legacy` | 旧版 `base`（`module: commonjs`、`moduleResolution: node`、`target: ES2015`）。仅用于回退；这些选项在 TypeScript 6 中已被标记为废弃。 |
| `@modern-js/tsconfig/react` | `base` 的别名，已废弃，请直接使用 `base`。 |

## 两份文件的布局

`tsconfig.json` 是唯一的主配置，所有路径别名（`paths`）都写在这里：

```json title="tsconfig.json"
{
  "extends": "@modern-js/tsconfig/base",
  "compilerOptions": {
    "noEmit": true,
    "types": ["node"],
    "paths": {
      "@/*": ["./src/*"],
      "@shared/*": ["./shared/*"]
    }
  },
  "include": ["src", "shared", "config", "modern.config.ts"]
}
```

项目有 BFF（`api/`）或自定义 Server（`server/`）时，在 `paths` 中追加 `"@api/*": ["./api/lambda/*"]`，并把 `api`、`server` 加入 `include`，然后添加：

```json title="tsconfig.server.json"
{
  "extends": "./tsconfig.json",
  "compilerOptions": {
    "module": "NodeNext",
    "moduleResolution": "NodeNext",
    "noEmit": false,
    "declaration": false
  },
  "include": ["api", "server", "shared"]
}
```

框架编译 `api/`、`server/`、`shared/` 以及开发时注册 ts-node 都会使用这份文件。这四个 `compilerOptions` 只覆盖各自的键，其余选项（包括 `paths`）全部继承自 `tsconfig.json`。它们与 `@modern-js/tsconfig/server` 的内容一致，直接写在文件内是因为 ts-node 10 不支持 `extends` 数组。

## 为什么需要两份文件

打包器希望看到 `module: ESNext`，而 Node 侧的产物必须与 `package.json#type` 一致：没有 `"type": "module"` 的项目需要 CommonJS 产物。同一份 `module` 取值无法同时满足两边，因此服务端单独覆盖模块选项。

## 没有 `tsconfig.server.json` 会怎样

框架按「`server.tsconfigPath` → `tsconfig.server.json` → `tsconfig.json`」的顺序解析服务端配置。只有回退到 `tsconfig.json` 且它的 `module` 是 ES Module 取值、而项目又不是 `type: module` 时，框架才会改用 `module: NodeNext` + `moduleResolution: NodeNext` 编译服务端代码，并打印一次警告。`type: module` 项目不会被改写。完整规则见 [server.tsconfigPath](/configure/app/server/tsconfig-path)。

## 迁移存量项目

旧版创建模板会在 `tsconfig.json` 中写入 `"baseUrl": "./"`，而 TypeScript 6 对任何 `baseUrl` 都会报 TS5101（该选项已废弃）。Modern.js 3 中已没有 `modern upgrade` 命令，存量项目通过迁移 Skill `modernjs-migrate-to-v3` 迁移。它的 `migrate.mjs` 会执行下面的 tsconfig 改写（已是 v3 的项目按续迁移处理），也可以只运行 tsconfig 这一步：

```bash
# 安装 Skill（--agent 可选 claude-code / codex / cursor 等）
npx skills add web-infra-dev/modern.js --skill modernjs-migrate-to-v3

# 只迁移 tsconfig；<skillDir> 为上一步安装的 Skill 目录
node <skillDir>/scripts/migrate-tsconfig.mjs <projectDir>
```

结果会写入 `<projectDir>/.agents/runs/modernjs-migrate/report.json` 的 `changed`（已自动改写）与 `manual`（需人工处理）。脚本可重复执行。

| 项目现状 | 脚本行为 |
| --- | --- |
| `baseUrl` 为 `"./"` 或 `"."`，且有 `paths` | 删除 `baseUrl`，`paths` 保持不变 |
| `baseUrl` 为 `"./"` 或 `"."`，但没有 `paths` | 不删除，列入人工清单：`import 'src/foo'` 这类依赖 `baseUrl` 的裸导入需要先用 `paths` 映射（如 `"*": ["./*"]`），再删除 `baseUrl` |
| `baseUrl` 为其他值（如 `"./src"`） | 不删除，列入人工清单，并给出改写后的 `paths` |
| 有 `api/lambda`，`paths` 缺少 `@api/*` | 补充 `"@api/*": ["./api/lambda/*"]`；如果 `baseUrl` 被保留，则列入人工清单，待 `baseUrl` 改写后再加 |
| 项目不是 `type: module`，有 `api/` 或 `server/`，没有 `tsconfig.server.json`，也没有配置 `server.tsconfigPath` | 写入上文的 `tsconfig.server.json` |
| `tsconfig.json` 含注释或尾逗号 | 不改写该文件，把上述改写列入人工清单 |

`baseUrl` 为其他值时，`paths` 中的每一项原本相对 `baseUrl` 解析，删除 `baseUrl` 前需要加上原 `baseUrl` 作为前缀，改成相对 `tsconfig.json` 所在目录：

```json title="迁移前"
{
  "compilerOptions": {
    "baseUrl": "./src",
    "paths": {
      "@/*": ["*"],
      "@shared/*": ["../shared/*"]
    }
  }
}
```

```json title="迁移后"
{
  "compilerOptions": {
    "paths": {
      "@/*": ["./src/*"],
      "@shared/*": ["./shared/*"]
    }
  }
}
```

不使用 Skill 时，按上表手动修改即可。

## 注意事项

- 不要在 `tsconfig.server.json` 中声明 `paths`：TypeScript 对 `paths` 是整体替换，而不是逐键合并。
- 不再需要 `baseUrl`。`paths` 中的相对路径以声明它的文件所在目录为基准。
- `@modern-js/tsconfig` 3.10 及以上版本需要搭配 `@modern-js/app-tools` 3.10 及以上版本使用。
