# 插件 API

Runtime 插件扩展普通页面和 Bridge 导出应用的初始化、根组件和清理行为。在 `src/modern.runtime.ts` 的 [`plugins`](/configure/app/runtime/plugins) 字段中注册插件。

## 插件结构与顺序

插件的 `name` 是唯一标识。`pre` 指定需要先于当前插件执行的插件名，`post` 指定需要在当前插件之后执行的插件名。`setup` 接收插件 API，可以返回 Promise。框架等待依赖插件的 setup 完成后再继续。

{/* prettier-ignore */}
```tsx
import type { RuntimePlugin } from '@modern-js/runtime'

export const preferencesPlugin = (): RuntimePlugin => ({
  name: 'preferences',
  pre: ['@modern-js/runtime-plugin-request-context'],
  setup(api) {
    const controller = new AbortController()
    api.onDispose(() => controller.abort())

    api.onBeforeRender(async context => {
      const url = new URL('/api/preferences', context.requestContext.request.url)
      const response = await fetch(url, { signal: controller.signal })
      context.preferences = await response.json()
    })
  },
})
```

每个挂载或服务端请求分别执行 setup。不要把当前语言、Request 或 loader 结果保存在模块级变量中。对象归属和完整阶段见[生命周期](./life-cycle)。

## 读取与更新

### `api.getRuntimeConfig`

返回当前 runtime 的配置。应将其视为只读数据，不能通过修改该对象存储请求状态。配置不是 React state。

### `api.getRuntimeContext`

返回当前实例的 context，与 `onBeforeRender` 参数引用同一个对象。页面数据、Bridge snapshot 和服务端 Request 由各自的数据源接入。内置插件消费当前实例的字段，不读取其他应用的 SSR globals。

内置请求上下文插件在 `setup` 中准备 `requestContext`，并在应用插件之前执行。应用的初始化数据和资源能力在创建实例时进入 context，路由匹配和 loader 结果则由 Router 在初始化阶段补充。

`ssr` 字段在 setup 前就绪，服务端初始化时为 true。在浏览器中，它表示当前页面或 Bridge 实例具有服务端初始化数据，不表示 React 水合是否已经完成。没有这些数据的 CSR 实例设为 false。

### `api.updateRuntimeContext`

将补丁深合并到当前 context，不会把补丁的根对象绑定为 context。这不是深复制。数组，以及被合并工具识别为复杂实例的对象（如 i18next 实例），保留按引用赋值的语义，后续修改这些共享值也会反映到 context 中。需要由实例独占的可变值，应为该实例单独创建或复制。

{/* prettier-ignore */}
```ts
const patch = { feature: { enabled: true } }
api.updateRuntimeContext(patch)
// 更新此普通对象字段时，再次提交补丁或修改当前 context
api.updateRuntimeContext({ feature: { enabled: false } })
```

内部 React Provider 使用当前 context，公开 `RuntimeContext` 提供隐藏框架字段的稳定视图，不维护第二份数据副本。直接修改字段不会自动触发 React 更新，需要响应式更新时使用 React state 或订阅。

### `api.getHooks`

返回当前实例的生命周期及扩展 hooks。普通应用的初始化由框架执行，不要在组件更新时手动重复调用初始化 hooks。

可以通过 `registryHooks` 工厂为每个实例创建新的扩展 hooks。如果 `registryHooks` 是由标准 helper 创建的 hooks 记录，Modern 会为每个实例复制 hook 容器，并保留静态定义中已注册的回调。任意第三方自定义 hook 的闭包无法自动复制，应在工厂内创建新 hook，不要返回共享的 hook 对象。

## 生命周期 API

### `api.onBeforeRender`

注册初始化回调。框架按插件依赖顺序执行并等待回调，随后才执行 `wrapRoot`。浏览器 props 更新和内部导航不会重复执行此阶段。

回调可以修改当前 context。抛出的错误或拒绝的 Promise 会终止初始化。需要主动中断时，使用第二个参数 `interrupt`。中断结果由平台适配器处理，不继续执行后续 hooks 或挂载。

{/* prettier-ignore */}
```ts
api.onBeforeRender((context, interrupt) => {
  if (context.requestContext.request.headers['x-maintenance'] === 'true') {
    return interrupt(new Response('Temporarily unavailable', { status: 503 }))
  }
})
```

### `api.wrapRoot`

注册根组件包装函数。它在初始化成功后调用一次，返回的组件在实例存续期间保持稳定。将 props 传给原始 App，保留更新和导航期间的页面状态。

{/* prettier-ignore */}
```tsx
import { RuntimeContext } from '@modern-js/runtime'
import { useContext } from 'react'

api.wrapRoot(App => {
  function PreferencesRoot(props) {
    const context = useContext(RuntimeContext)
    return (
      <PreferencesProvider value={context.preferences}>
        <App {...props} />
      </PreferencesProvider>
    )
  }
  return PreferencesRoot
})
```

Router 插件的 `api.modifyRoutes` hook 负责修改实例路由。需要修改路由的插件应声明对 Router 插件的依赖，不使用模块级可变路由表。

### `api.onDispose`

注册当前实例的同步清理函数，用于移除监听器、清理定时器、取消在途工作和释放插件创建的资源。清理按注册顺序逆序执行，每个实例只执行一次。

卸载、请求输出结束、初始化失败或取消都会释放实例。已释放实例中新注册的清理函数立即执行，因此异步获得资源后仍应立即注册清理。异步操作自身需要响应 AbortSignal，不应仅在卸载后忽略 React 更新。
